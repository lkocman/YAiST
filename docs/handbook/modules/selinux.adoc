[.operation]
****
Show recent SELinux AVC denials from the audit log. Use this when something fails with 'permission denied' and SELinux may be the cause.

*Command:* `/selinux denials` +
*Runs:* straight away; it only reads the system.

[horizontal]
`limit`:: How many denials to show (default: `10`)

.In the terminal
[source,shell]
----

[[selinux.set_boolean]]
[.operation]
****
Turn an SELinux boolean on or off.

*Command:* `/selinux set-boolean BOOLEAN false` +
*Runs:* after you confirm. YAiST, or the assistant, first shows a plan with the commands it stands for.

[horizontal]
`boolean`:: Boolean name, e.g. httpd_can_network_connect (required)
`value`:: On (true) or off (false) (required)
`persistent`:: Keep the setting after reboot (default: `true`)

.In the terminal
[source,shell]
----
sudo setsebool -P BOOLEAN off
----

=== Set mode

// TODO(handbook): when and why to use this, then how it looks in YAiST.

// BEGIN GENERATED selinux.set_mode -- written by `yaist docs` from the module's code; edit the code, not this block
[[selinux.set_mode]]
[.operation]
****
Switch SELinux between enforcing and permissive until the next reboot. Permissive only logs denials and weakens security.

*Command:* `/selinux set-mode enforcing` +
*Runs:* after you confirm. The plan is marked in red: this is hard to undo or changes what the system trusts, so read it before you agree.

[horizontal]
`mode`:: New mode: `enforcing`, `permissive` (required)

.In the terminal
[source,shell]
----
sudo setenforce 1
----
****
