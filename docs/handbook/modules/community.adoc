=== Report a problem

// TODO(handbook): when and why to use this, then how it looks in YAiST.

When a change fails, YAiST offers to report it: a prefilled openSUSE
Bugzilla report when a package is at fault, or a YAiST issue when YAiST
got it wrong, with the likelier one first. The report already holds what
was run and its output; you add what you expected, and nothing is sent
until you submit it in the browser.

[[community.report_problem]]
[.operation]
****
Prepare a bug report: a YAiST issue on GitHub (target yaist) when YAiST got something wrong, or an openSUSE Bugzilla report (target opensuse) for a problem in the distribution or a package. It opens prefilled in the browser; the user completes it there, and nothing is sent until they submit it.

*Command:* `/community report-problem title=TITLE observation=OBSERVATION` +
*Runs:* straight away; it only reads the system.

[horizontal]
`target`:: yaist: YAiST did something wrong; opensuse: a package or the distribution is broken: `yaist`, `opensuse` (default: `yaist`)
`title`:: One line saying what is wrong, e.g. 'Update fails: %post script of foo exits 1' (required)
`observation`:: What happened: the steps and the exact error output (required)
`expected`:: What should have happened (optional)
`reproducible`:: Does it happen again?: `always`, `sometimes`, `once`, `unknown` (default: `unknown`)

.In the terminal
[source,shell]
----
# check for an existing report first, then:
xdg-open 'https://github.com/lkocman/YAiST/issues/new?template=bug_report.yml'
----
****
