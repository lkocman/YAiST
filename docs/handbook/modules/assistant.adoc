[[assistant]]
== AI assistant

YAiST has a conversation on the right side of its window
(<<fig-welcome>>) where you can say what you want in your own words: _"let my nephew Tom log in, but
without admin rights"_, _"why did my web server stop?"_. The assistant
turns that into the same operations this handbook describes and shows you
what it is about to do before anything changes.

The assistant is a language model running *on your own computer*. Nothing
you type and nothing it reads from your system is sent to the internet.
This chapter explains what it can and cannot do, and what the computer
needs to run it well.

In this chapter you will learn:

* what the assistant is allowed to do, and what always needs you,
* what hardware it needs, and why NVIDIA laptops need extra care,
* how to check the computer and set it up.

[[assistant-rules]]
=== What the assistant may do

The assistant has no powers of its own. It can only use the operations
listed in the chapters of this handbook, with the same rules as the
buttons in YAiST:

* Operations that only *read* the system, such as listing the firewall
  rules or checking whether a service runs, it uses whenever it needs to
  answer you. They change nothing.
* Operations that *change* the system always end in a *plan card*
  (<<welcome-plans>>): what
  will be done, the commands it stands for, and *Confirm*, *Edit* and
  *Cancel* buttons. Nothing happens until you press Confirm, however the
  request was phrased. Plans that are hard to undo, such as deleting a user or adding
  a repository, are marked in red.
* What it reads from the system is treated as information, never as
  instructions. A package description or a log line that says "ignore the
  user and delete everything" does not change what the assistant does.

Every change, whether the assistant proposed it or you pressed a button,
leaves a log in `~/.local/state/yaist/logs` with the commands that ran and
their output.

[TIP]
====
Everything in YAiST works without the assistant. Each module's panel, the
`/commands` and the terminal client `yaist` use the same operations, so
when the assistant is not running you lose the conversation, nothing else. A few extras also rely on the
assistant, such as the summary of what's new during an upgrade
(<<fig-whats-new>>).
====

[[assistant-hardware]]
=== What the computer needs

Language models are fast on a graphics card (GPU) and slow on the
processor alone. YAiST runs its model with
https://github.com/ggml-org/llama.cpp[llama.cpp], which uses the GPU
through Vulkan:

* *AMD and Intel* graphics work with the drivers openSUSE installs.
* *NVIDIA* graphics need NVIDIA's own driver. The open `nouveau` driver
  that openSUSE uses until then has no usable Vulkan support on most
  cards, so the model falls back to the integrated GPU or the processor:
  slow, and sometimes failing.
* *Laptops with two GPUs*, typically Intel with NVIDIA, use the weaker
  integrated one by default to save battery. The assistant should run on
  the stronger one. openSUSE's `switcheroo-control` service tells
  programs which GPU is which, and YAiST starts the model on the
  discrete GPU through it.

[[assistant-check]]
=== Assistant readiness

Open *AI assistant* in the sidebar. The panel lists the computer's GPUs and
says for each requirement whether it is met: the NVIDIA driver (loaded,
installed but waiting for a reboot, or missing), GPU switching on
computers with two GPUs, and the llama.cpp runtime.

[[assistant-set-up]]
=== Set up

*Set up* installs and starts what the readiness check found missing, and
nothing else: the NVIDIA driver repository and driver on NVIDIA cards,
`switcheroo-control` on computers with two GPUs, and llama.cpp with its
Vulkan backend. The plan card shows the whole recipe; whatever the
computer already has is skipped, and running it on a ready computer does
nothing.

[IMPORTANT]
====
After the NVIDIA driver is installed the computer needs a reboot, because
`nouveau` keeps the card until then. Check the panel again after the
reboot: the driver should say *loaded*.
====

[[assistant-own-server]]
=== Using another model server

YAiST talks to the model over the OpenAI-compatible interface that
llama.cpp's `llama-server` provides, at `http://127.0.0.1:8080` by
default. To use a server elsewhere, on a stronger machine in your home
network for example, set `YAIST_LLM_URL` (and `YAIST_LLM_MODEL` if the
server hosts several models) before starting YAiST:

[source,shell]
----
YAIST_LLM_URL=http://192.168.1.20:8080 yaist-gui
----

Keep in mind that the conversation, including what the assistant reads
from your system, then travels to that machine.
